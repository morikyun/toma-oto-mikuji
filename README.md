# とおまの音みくじ — いまのあなたに、響く一曲を。

5つの質問に答えて、總水とおまさん・カミムスヒの8作品51曲から一曲に出会う、非公式ファンサイトです。月の光とガラガラの演出を楽しみながら、いまの気分に響く音楽を探せます。

[サイトを見る](https://toma-oto-mikuji.pages.dev/) · [修正・新しいページをお願いする](https://github.com/morikyun/toma-oto-mikuji/issues/new/choose) · [用語の意味を知る](#はじめてのgithub用語案内)

## 修正・新しいページのご相談

「ここを直してほしい」「こんなことができると嬉しい」という声をお待ちしています。**ITの知識は必要ありません。いつもの言葉で教えてください。**

GitHubでは、このような依頼を **Issue（イシュー）** と呼びます。音みくじへのご要望を運営に伝える「連絡票」のようなものです。

サイトのフッターにある **「サイトへのご要望」** からも、Issueのフォーム選択画面を開けます。

### まず、お願いしたいことを選びます

フォームを選ぶと、**Type（種類）とラベルが自動で付きます。** Typeは依頼を大きく分ける種類で、Task（作業・対応）・Bug（不具合）・Feature（追加・改善）の3種類です。ラベルは詳しい内容を示す「色付きの付箋」です。迷ったときは「質問・相談したい」を選んでください。

- **[文章・曲名・リンクを直したい](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=01-change.yml)**：曲の紹介文、質問の文章、リンク先の修正や情報の追加など。Typeは「Task」、ラベルは「説明文・案内」。
- **[新しいページを作ってほしい](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=02-new-page.yml)**：音みくじの楽しみ方など、まだサイトにない案内ページの提案。Typeは「Feature」、ラベルは「改善・追加」。
- **[表示がおかしい・うまく動かない](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=03-problem.yml)**：文字が重なる、抽選が進まない、ボタンやリンクが反応しないなど。Typeは「Bug」、ラベルは「不具合」。
- **[見やすく・使いやすくしてほしい](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=04-usability.yml)**：文字の大きさ、色、配置、質問の選びやすさなど。Typeは「Feature」、ラベルは「見やすさ・使いやすさ」「改善・追加」。
- **[機能を追加・改善してほしい](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=05-feature.yml)**：選曲や楽曲検索、結果の共有など、できることを増やす提案。Typeは「Feature」、ラベルは「改善・追加」。
- **[質問・相談したい](https://github.com/morikyun/toma-oto-mikuji/issues/new?template=06-question.yml)**：音みくじの内容や使い方の質問、まだまとまっていない相談。Typeは「Task」、ラベルは「質問・相談」。

### 登録のしかた

1. **上のリンクからフォームを開きます。** 登録にはGitHubのアカウントが必要です。ログインを求められたら **Sign in（ログイン）** へ進んでください。アカウントがない方は **Sign up（アカウント作成）** から作成できます。ログイン後、もう一度上のリンクを開くとフォームに進めます。
2. **タイトルを書きます。** 例：「結果画面の曲の紹介文を変えたい」。最初から入っている `[修正]` などの後ろに、お願いしたいことを短く足してください。
3. **質問に沿って入力します。** 必須の項目だけでも送れます。URLが分からなければ空欄で大丈夫です。結果画面なら「結果をシェア」でリンクをコピーできます。画像は文章を書く欄に貼り付けるか、欄の下の添付ボタンから追加できます。
4. **画面下の「Create（作成）」または「Submit new issue」を押します。** 登録できると依頼のページが開き、「#3」のような番号が付きます。そのページのURLを控えておくと、あとから確認できます。

GitHubの上部メニューからは **Issues → New issue** でも同じフォームを開けます。スマートフォンなどでは、メニューが「…」の中にあることもあります。

### 修正依頼の記入例

結果画面の紹介文を変えたい場合は、このくらいの説明で大丈夫です。

- **どの画面？** 「誓い」が選ばれた結果画面
- **どの部分？** 曲名の下にある紹介文
- **どう変えたい？** 初めてこの曲を知った人にも伝わるように、もう少し短くしてほしい。

質問が分かりにくいときは、**「何問目か」「どの言葉で迷ったか」「どうなると選びやすいか」** を教えてください。例：「2問目の選択肢で迷ったので、それぞれの説明をもう少し具体的にしてほしい」。

曲の解説に情報を足したいときは、**曲名と、参考になる公開配信・公式記事のURL** があると確認しやすくなります。例：「『この曲を、もう少し深く。』に、とおまさんがこの曲について話している配信を追加してほしい。〇分〇秒ごろから話しています」。歌詞や配信内容の全文を貼る必要はありません。

新しいページなら、**「どんなページか」「誰に何を伝えたいか」「載せたい内容」** を教えてください。文章や見た目がまだ決まっていなくても、「相談したい」と書いてもらえれば大丈夫です。

### 登録したあとは

運営が依頼を確認し、必要があればそのページのコメント欄でお聞きします。補足や訂正もコメントに書けます。対応内容を確認してからサイトへ反映するため、登録と同時にサイトが変わるわけではありません。依頼した方がサイトのファイルを編集する必要はありません。

運営者が確認した依頼をもとに、Codexを使って修正案を作成します。**Issueを登録しただけで、AIが自動的に修正・公開する仕組みではありません。** 確認用サイトの公開や、実際のサイトへの反映は、もりきゅんさんが内容を確認してから進めます。

### 投稿するときに気をつけること

GitHubのユーザー名と、入力した文章・コメント・添付画像は、誰でも見られる状態で公開されます。メールアドレス・電話番号・住所などの個人情報、パスワード・APIキー・トークンは書かないでください。画像にも個人情報が写らないようにしてください。

非公開の資料やアーカイブ、歌詞・記事の全文は載せず、参考になる公開ページのURLでお知らせください。紹介文やリンク先の変更は、運営が公式情報などで確認してから反映します。

個人情報の取り扱いに関するご相談は、公開のIssueではなく、サイトの[お問い合わせ窓口](https://toma-oto-mikuji.pages.dev/privacy/#contact)をご利用ください。

## はじめてのGitHub用語案内

聞き慣れない名前も、身近なものに置き換えると少し分かりやすくなります。ここでは、音みくじの修正をお願いするときの使い方に沿ってご紹介します。

### GitHub（ギットハブ）とは？ — みんなで使う「資料室と作業場」

サイトの材料となる文章やプログラムを保管し、修正の相談や変更の記録をまとめられるインターネット上のサービスです。みんなで会報を作るときの、原稿を置く棚と、相談用の掲示板が一緒にある場所をイメージしてください。

音みくじでは、サイトの資料をここに置き、「ここを直してほしい」という声も受け付けています。普段の言葉で相談できます。

### Issue（イシュー）とは？ — お店に渡す「ご要望カード」

「何に困っているか」「どうしてほしいか」を、一件ずつ書いて相談する場所です。お店のご要望カードに「この商品を置いてほしい」と書くように、「この曲の紹介文を変えてほしい」と伝えられます。

たとえば「結果画面の説明を、スマホでも読みやすくしてほしい」という依頼が一つのIssueになります。登録すると専用のページと番号が付き、同じページで補足や質問をやり取りできます。

### Pull Request（プルリクエスト／PR）とは？ — 印刷前に見てもらう「確認用の原稿」

作業した人が、実際に直した内容を見せて「この変更を取り入れてよいですか」と確認をお願いするものです。会報の原稿を直したあと、印刷する前に担当者へ見てもらう場面に似ています。

先ほどの例なら、文字を大きくした人が「この見え方に変更しました。確認してください」とPRを出します。運営者は変更内容を確認し、必要なら直してもらってから採用します。**Issueは「こうしてほしい」という依頼、PRは「こう直しました」という変更案**と覚えると分かりやすいです。

### 依頼がサイトに反映されるまで

1. **Issueで依頼する**：「曲の紹介文を変えてほしい」とご要望カードを渡します。
2. **担当者が修正し、PRを出す**：運営が確認した依頼に沿って、直した文章を確認用の原稿として提出します。
3. **運営者が確認してマージする**：もりきゅんさんが変更内容と確認用サイトを確認し、問題がなければ正式な内容として採用します。
4. **サイトに反映される**：このサイトでは、マージ後の自動チェックと公開処理が成功すると、Cloudflare Pagesのサイトに反映されます。

依頼する方は、まずIssueを書ければ大丈夫です。補足が必要なときは、運営がコメントでお聞きします。

### ほかに見かける言葉

- **README（リードミー）**：今読んでいる、この案内文です。お店の入口にある「ご利用案内」のように、この場所の目的や使い方を紹介します。
- **リポジトリ**：一つのサイトや活動に関する資料・記録をまとめる場所です。GitHubが資料室なら、音みくじ専用の棚がこのリポジトリです。
- **Type（タイプ／種類）**：依頼を大きく分ける「書類の分類箱」です。Taskは作業や相談への対応、Bugは不具合、Featureは追加や改善を表します。選んだフォームに合う種類が一つ、自動で付きます。
- **ラベル**：依頼を分類する「色付きの付箋」です。選んだフォームに応じて「不具合」「質問・相談」などの目印が自動で付きます。運営が内容を確認し、あとから調整することもあります。
- **コメント**：依頼や変更案のページに書き足すメッセージです。連絡帳の返事のように、質問・補足・訂正をやり取りできます。
- **プレビュー**：変更を正式に公開する前に、見え方や動きを確認するためのサイトです。音みくじでは、運営者が承認してから用意します。
- **マージ（Merge）**：確認した変更案を正式な内容に取り込むことです。修正した原稿にOKを出して、正式版に差し替えるイメージです。このサイトでは運営者が行います。
- **クローズ（Close）**：その依頼や変更案に区切りを付けることです。連絡票を「対応済み」や「今回は見送り」として片付けるイメージです。閉じた理由はコメントなどで確認できます。
